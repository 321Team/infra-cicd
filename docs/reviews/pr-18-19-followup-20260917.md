## 1. 발견한 문제와 수정

`tools/delivery/app_evidence.py:safe_file()`은 일반 파일 검사 전에 `os.open(O_RDONLY)`를 호출했다.
입력이 FIFO이면 writer가 연결될 때까지 멈춰 `fstat`의 파일 종류 검사에 도달하지 못했다.
실행 승인 우회나 거짓 PASS 문제가 아니라 증적 수집/검사 도구의 가용성 결함이다.

- 수정: `O_NOFOLLOW`를 유지하며 `O_NONBLOCK`를 추가한다. FIFO를 열어도 기다리지 않고 기존 일반 파일 검사에서 거부한다.
- 회귀: 실제 CLI의 expected JSON, 수신 archive, result receipt, raw command log 경로에 각각 FIFO를 두었다.
- 수정 전: 네 경로 모두 3초 내 종료하지 못해 시험이 TimeoutExpired로 실패했다.
- 수정 후: 네 경로 모두 rc1, `EVIDENCE_CHECK=FAIL`, `DELIVERY_GATE=NOT_VERIFIED`, stderr 없음으로 종료하며 export 디렉터리를 만들지 않는다.
- 일반 파일의 해시·크기·symlink·변조 검사와 기존 PASS/BLOCK/FAIL 의미는 유지한다.
- 범위: 증적 도구1개·회귀 시험1개(4개 하위 사례)·이 문서. 앱 Workflow·입력 config·공급 수집기·서버 실행본은 변경하지 않는다.
