# Phase 1 CICD Token 900초 정책 정합화

기준: 2026-10-10 KST. Phase 1 인수 작업의 기존 단기 ServiceAccount Token 소비 계약을 정합화한다.

정책 근거는 [PR160 R1/R2 담당자 회신](https://github.com/321Team/fds-project-baseline/pull/160#issuecomment-6084886811)과 [PR161의 동일 회신 재확인 리뷰](https://github.com/321Team/fds-project-baseline/pull/161#pullrequestreview-5477670195)다. 요청 900초·최대 수명 900초가 채택값이며, 과거 발급 스크립트의 3600초를 별도 허용값으로 해석하지 않는다. Phase 2 사전작업이나 새 권한·정책 결정은 포함하지 않는다.

## 현재 코드 계약

`delivery_gate.py`의 `TOKEN_REQUEST_SECONDS=900`, `TOKEN_MAX_SECONDS=900`, `TOKEN_POLICY_REFERENCE`를 공통으로 소비한다. reference는 위 R1/R2 회신 URL과 정확히 일치해야 한다.

| 경로 | 필수 조건 |
| --- | --- |
| Delivery pre-deploy / v1 binding / v2 plan | 정수 요청 TTL=900. bool·문자열·899·901·3600 거부. 정책 reference exact match |
| Native TokenRequest | 요청900초. 요청 응답의 UID·audience·expirationSeconds 결속과 실제 JWT/status expiry 제한 유지 |
| 주입 credential / native credential | 실제 JWT `0 < exp-iat <= 900`. 901·3600 거부. fresh TokenReview 및 exact SA UID/audience 확인 |
| 실제 사용 가능 시간 | 검증된 JWT와 native status의 더 이른 만료, wall/monotonic 잔여시간으로 제한. 요청값으로 수명을 합성하지 않음 |

요청900초라도 실제 발급 수명은 더 짧을 수 있다. 기본 배포 시작 예산은 기존 `2 × timeout300 + margin30 = 630초`이며 승인 잔여시간과 실제 credential 잔여시간이 각각 이를 충족해야 한다. 잔여630초는 시작 가능, 629초는 `CREDENTIAL_WINDOW_TOO_SHORT`로 시작을 차단한다. 시작 가능은 완료 보장이 아니다. 각 호출의 만료 재확인, 실패·권한 소실 시 추가 쓰기 중단, private credential 정리는 유지한다.

별도의 Deploy 승인 창, probe 실행 허용 창, 일반 timeout 상한의 3600초는 Token 수명 상한이 아니다. 이 변경으로 그 값을 바꾸거나 승인시간을 연장하지 않는다.

## 기존 입력·증적 처리와 다음 실행

1. 과거 3600초 plan/record/approval 및 원본 영수증을 수정하지 않는다. 새 코드에서 재사용하면 차단된다.
2. 다음 실행의 정확한 Source/Workflow·Push receipt·대상 두 Deployment/이전 digest·CA·현재 승인 창을 확인한 뒤 요청 TTL900 및 현행 reference를 가진 새 입력 bytes를 만든다. 새 입력 hash에 결속된 승인 기록을 사용한다. 기존 승인의 hash를 자동으로 교체하지 않는다.
3. 실제 Token의 UID·audience·JWT 시간·fresh TokenReview와 더 이른 native expiry를 확인한다. 필요한 시작 예산이 부족하면 발급값을 늘리거나 자동 재발급하지 않고 중단한다.
4. Token 만료·권한 소실 이후 자동 rollback을 시도하지 않는다. pending/unknown 영수증과 원본 로그를 보존하고 기존 수동 조정 절차로 인계한다.
5. R2의 만료 전 credential 정리는 현재 소비자 확인과 결속한다. 기존 Push 성공만으로 Worker Pull·실제 소비자 검증을 대체하지 않는다.

## 검증 경계

추가 회귀 시험은 900초 정상 경로, 901·3600 거부, 더 짧은 실제 수명, 630/629초 시작 예산, 과거 승인 hash 재사용 차단을 다룬다. 시험 JWT/TokenReview는 합성 MOCK이며 실제 발급·인증·배포 증적이 아니다.

이 코드 변경의 `RUNTIME=NOT_RUN / DELIVERY_GATE=NOT_VERIFIED`다. Source/MOCK/CI/REVIEW/MERGE 상태는 해당 PR 기록에서 각각 확인한다. 기존 Runtime 증적의 상태나 티켓 AC를 이 변경만으로 완료 처리하지 않는다.
